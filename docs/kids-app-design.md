# 子ども向けアプリのデザインポイント

keisan（小1向け計算練習）のユーザーテストと実装で得た知見。子ども向けアプリを作る・直すときに読む。

## 文字と言葉

- **対象学年で「読める文字」を先に定義する**。小1前半ならひらがなのみ。カタカナは習いたて、漢字は不可
- 時間・日付の記号表記は未習: 「1:17」「8/10」は読めない（分数や点数に誤読される）→「1ぷん17びょう」「8がつ10にち」
- **見出し語こそ読める必要がある**（タイム／ノーミス／ベスト → かかったじかん／ランキング）。説明文はどうせ読まれない前提で作る
- ゲーム文脈のカタカナ（スタート、ランキング）は許容されることも多い。保護者と認識合わせして決める

## 操作

- タップ領域は44px以上。**破壊的操作（終了✕・削除）は他ボタンの隣に置かない**（左右に分離する）
- 進行が消える操作には確認を挟む。確認中はタイマーを止めて不利にしない
- 子どものタップは2連イベントになる前提で作る: 正解後の入力ロック、誤答カウントは300ms級のデバウンス
- 画面下端はOSのジェスチャー領域。キーパッド等の主要ボタンは下端から30px以上離す

## フィードバック

- **失敗を責めない**: バツ・ブザー・失敗回数の強調はしない。小さな震え＋低音だけにして、すぐ押し直せるようにする
- 成功は身体感のあるメタファーで祝う（赤えんぴつのまる、💮はなまる、スタンプ）
- **完走は新記録でなくても必ず祝う**。新記録はさらに別格の演出（紙吹雪＋ファンファーレ）にして差をつける
- テンポ最優先。正解演出は250ms級で切り上げて次の問題へ（気持ちよさより待たせないこと）

## レイアウト

- 可変要素（ヒント表示、桁数、記録の有無）があっても**数字や記号の位置がブレないよう固定スロットのグリッド**にする
- 大きな文字を並べるときは `line-height: 1` に統一しないと下端が揃わない（1つでも既定値継承があると浮く）
- 状態によって高さが変わる要素はガタつきの元。行を常設して高さを固定する（未記録は「−−」表示など）

## 数の表現（算数系）

- 数は5と10のまとまりで見せる（ドット1〜5個目は黄、6個目以降は赤。2桁が出るモードは10個で改行）
- 出題は学習範囲に正確に合わせ、**検算する**（「くりあがりの問題」は全問本当にくりあがるか）
- 答えの範囲がキーパッドから推測できてしまう構成（答えが必ず11以上等）は、練習効果を狭めることを意識する

## データ

- GitHub Pages は同一オリジンなので localStorage キーはアプリ名プレフィックス必須（AGENTS.md の規約）
- 公平性が変わるモード（問題数など）の記録は別枠のキーに保存する
- 履歴の件数切り捨てでベスト記録が消えないようにする
- 保護者向けに「個人開発・データは端末内のみ」の注記を置く
